TL;DR:TL;DR RoboMemo turns everyday smart-glasses recordings into a memory of your personal items and preferences. On the robot side, its execution harness has a System 2 / System 1 design: System 2 retrieves the relevant memory, reasons over it and the live camera views with Gemini Robotics-ER 2 to decide whether to act, then issues a language instruction to System 1, the Gemini Robotics On-Device VLA, which turns it into motor actions. So the robot picks up your mug from a group of look-alikes, reaches for your tea rather than a coworker's, and holds off when your item isn't on the table.

AbstractAbstract

Generalist vision–language–action (VLA) policies have emerged as a general-purpose paradigm for instructing robots in natural language across diverse manipulation tasks. However, personalized requests such as “put my mug in the tray” refer to a specific object among visually similar ones, and resolving them requires user-specific context that is currently hand-crafted through explicit descriptions or dedicated reference photographs of each object. To address this limitation, we present RoboMemo, a two-stage system that recovers this context by leveraging everyday smart-glasses recordings. An offline distillation stage links observed interactions to object instances and builds a Personal Context Store of natural-language descriptions and reference crops. At runtime, an execution harness conditions a frozen VLA policy on the retrieved attributes and verifies object identity against live camera views before execution, refusing when the requested object is absent, without modifying the policy itself.

We demonstrate on ALOHA 2, across 112 real-robot episodes, that RoboMemo performs on par with manual hand-crafted context on instance selection, pickup, and task completion, while requiring no per-object capture or annotation. In the near-twin robot study, RoboMemo picks up the correct mug in all five target-present trials that proceed to execution (5/6 overall, versus 0/6 for No Context), and correctly refuses in all eight target-absent trials. On a 12-hour multi-day corpus, RoboMemo additionally improves evidence-supported retrieval of object queries over a flat-memory baseline. These results suggest that a household robot could be personalized before its first day of use, from recordings its owner already makes, rather than through a dedicated setup session for every object. We will release the RoboMemo pipeline along with the harness module to facilitate future research on personalized robot manipulation.

“My” Means One Specific Object

“Put my sunglasses into the tray” means one particular pair. When several similar pairs are on the table, looks alone can't tell the robot which one is yours. What you have done with them before can.

Key Findings

01

Automatic memory works as well as writing it by hand

Descriptions and photos pulled automatically from smart-glasses footage give the same 14/16 correct choices and 9/16 finished tasks as hand-written descriptions with photos taken for the purpose. Nobody has to photograph or label each object.

02

Photos, not words, tell near-twins apart

When only a look-alike of the user's mug is on the table, RoboMemo refuses before moving in 8/8 trials (0/8 for the category-level baseline). Words alone can't separate two near-identical mugs: in offline tests, a description confirmed the right one in 0/36 cases, while reference photos from the recordings got 30/36.

03

What's left to fix is grasping, not recognition

RoboMemo picks the intended object in 14/16 trials but finishes the task in 9/16. The remaining failures happen while grasping or placing the object, not while recognizing it.

Everyday Smart-Glasses Capture

There is no setup session for each object. Two members of the author team wore smart glasses during their own work, and their objects show up in the footage as they pick them up, carry them and put them down. RoboMemo mines its personal context from these recordings.

System

RoboMemo works in two stages. Ahead of time, it goes through the user's recordings and builds a Personal Context Store of their objects. When a request comes in, it looks up what it knows about the object, checks that the object is really in front of the robot, and only then hands a more specific instruction to an off-the-shelf robot policy (a VLA). The policy itself is never retrained.

a

Offline personal context distillation

Builds a memory of the user's objects from days of recordings, before any robot is involved.

  • Privacy first. EgoBlur blurs faces and license plates before anything else runs.
  • Spot interactions. Qwen3-VL watches overlapping 20 s windows and notes when the wearer handles an object.
  • Outline the object. SAM 3 outlines objects of the named category (say, “mug”) in up to three frames.
  • Keep the best views. A second Qwen pass keeps up to two clear crops per interaction, or none when it isn't sure.
b

Query resolution

Finds the evidence behind a request like “my mug”.

  • Search. Keyword search (BM25) and embedding search (TIPSv2-L14) each rank the stored entries, and the two rankings are merged.
  • Pick the evidence. A vision-language model looks at the top matches and chooses the description and reference images that fit.
  • Hand off. The category, description and reference images go to the robot side as one bundle.
c

Execution with personal context

Checks first, then lets the unchanged policy do the moving.

  • Verify. Gemini Robotics-ER 2 compares the reference images with live views from above and from table height.
  • Act. Only when the object is CONFIRMED does Gemini Robotics On-Device get an instruction that names its look, like “the red sunglasses”.
  • Follow up. ER2 checks at set points whether the task is done, and restarts the policy if it isn't.

A question counts as strictly supported only if the answer is right and every image returned as proof really shows the object, at the right time or across the right sessions. A human judged the answers without knowing which method produced them. Flat Memory is a simpler baseline that shares RoboMemo's event detection and candidate crops but picks crops by category, closeness to the hand and confidence, without RoboMemo's visual check. RoboMemo raises the semantic-weighted strict score from 46.4% to 72.5% (+26.1 points), mostly on questions that span several sessions, while storing fewer crops (142 vs 203), more of which clearly show the object (81.7% vs 70.4%).

FAQ

Does RoboMemo fine-tune the robot policy?

No. The robot policy (Gemini Robotics On-Device) is used as-is for every user and task. RoboMemo only changes the text instruction it receives, for example “the red sunglasses” instead of “my sunglasses”, and decides whether to run it at all. The reference images and ER2's target point are never passed to the policy.

What happens when the requested object isn't there?

The robot refuses before it moves. First, Gemini Robotics-ER 2 compares the reference images with live views from above and from table height. If the memory has nothing for the request, or the check comes back ABSENT or CONTRADICTED, the robot refuses. If it comes back UNVERIFIABLE, the robot looks again, up to two tries.

How are the recordings kept private?

EgoBlur blurs detected faces and license plates before processing, and recording environments were inspected beforehand to exclude bystanders, visible personal identifiers and confidential materials. Distillation runs locally on a single workstation (NVIDIA RTX PRO 6000 Blackwell) with Qwen3-VL-30B-A3B-Instruct and SAM 3.

What data and hardware were used?

A 12-hour corpus recorded over multiple days in a multi-room office by two members of the author team, with four object pairs (mugs, notebooks, sunglasses, pouches). Robot trials ran on ALOHA 2, where the policy sees four camera views and plans 50 steps of motion at a time, run at 50 Hz (one second per chunk).

What are the limitations?

RoboMemo can pass personal context to the policy only as words from a fixed instruction vocabulary, so once the robot is moving, picking the right object is up to the policy. It also assumes objects don't change how they look or who owns them, and the detail that tells two objects apart (like a printed logo) can face away from the cameras. Most remaining failures happen while grasping and placing, not while recognizing the object.

Will the code be released?

Yes. We will release the RoboMemo distillation pipeline and execution harness. Public access to ER2 and Gemini Robotics On-Device is subject to their providers' requirements.
